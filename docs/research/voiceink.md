# VoiceInk 技术调研与后续演进方向

> 调研日期：2026-11-05  
> 参考项目：[Beingpax/VoiceInk](https://github.com/Beingpax/VoiceInk)（macOS 原生开源语音输入与 AI 听写应用）

---

## 1. 为什么 VoiceInk 是极具价值的参考标杆？

VoiceInk 是目前开源社区中成熟度高、且与 **Voice Buddy** 在产品愿景高度重合的项目：
1. **产品定位重合**：均以替代 Superwhisper、Wispr Flow 等高昂订阅制云端听写软件为目标，主打 **100% 离线、隐私优先、本地运行**。
2. **技术栈高度契合**：基于 100% 原生 Swift（SwiftUI + AppKit + CoreAudio + Accessibility），深度利用 macOS 系统级 API 实现全局快捷键与跨应用文本插入。

## 2. VoiceInk 值得我们深度借鉴的核心功能

### 2.1 上下文感知场景模式（Context-Aware App Modes / Profiles）
- **功能机制**：
  检测当前正在输入的前台应用（如通过 Bundle ID / 进程名），并自动匹配该场景下的整理 Prompt 与格式化倾向：
  - **代码编辑器 / 终端（Xcode, VS Code, Cursor, iTerm）**：倾向于保留英文变量名、驼峰/下划线命名法，不随意将英文缩写翻译为汉字，保留特殊符号。
  - **邮件与文档客户端（Mail, Outlook, Word, Pages）**：倾向于商务正式口吻，规范标点分段，自动修饰书面语。
  - **即时通讯应用（微信, Slack, Telegram, 飞书）**：保留自然的口语节奏与短句，不做过度书面化重写。
- **Voice Buddy 的现状与切入点**：
  Voice Buddy 在 [`App.swift`](../Sources/VoiceBuddyApp/App.swift) 中已经捕获了 `targetPID` 与 `targetAppName`，当前插入前已掌握目标上下文。后续只需在设置中引入“场景规则映射表”，在调用文本整理流水线时注入应用专属上下文提示词即可。

### 2.2 自定义词典与纠错自学习（Custom Vocabulary & Auto-Learn）
- **功能机制**：
  - **静态词库**：允许用户在设置中自定义高频人名、技术缩写、公司内部专有名词（如“Qwen”、“DeepSeek”、“MLX”），并作为偏置词注入到 ASR 或后整理流水线中。
  - **动态自学习**：当用户在目标应用中手动修正刚才语音输入的词汇时，系统捕获该修改并提示或自动收录到用户词库。
- **价值**：
  通用语音大模型（如 Whisper、Qwen）在冷门人名、专业术语上容易产生同音错字。专有词典是彻底解决“高频专有名词识别错误”的最高效途径。

### 2.3 本地历史记录归档与检索（Searchable Dictation History）
- **功能机制**：
  在本地通过轻量 SQLite 或 JSON 文件持久化每次听写的元数据：时间戳、原始 ASR 识别文本、模型整理结果、目标应用名以及录音时长。
- **价值**：
  - **容错防丢**：当第三方应用（如某些特定网页或无响应应用）导致自动粘贴丢失时，用户可一键呼出历史记录重新复制。
  - **灵感速记与备忘**：用户日常随口说出的想法无需额外打开备忘录，历史看板本身就是轻量灵感库。

### 2.4 听写与助手双模态切换（Dictate vs. Assistant Mode）
- **功能机制**：
  除了常规的“输入框听写上屏”外，提供辅助快捷键（如按住另外的快捷键说话）：
  - 用户先选中一段文字，按住助手快捷键发出语音指令（如：“翻译成地道英文”、“提取核心要点并列出三个待办”）。
  - 大模型直接在原地替换或弹出浮窗回答。
- **价值**：
  将工具从单一的“语音打字机”升维为“全局语音 Copilot”。

## 3. Voice Buddy 与 VoiceInk 的深度对比

| 维度 | Beingpax/VoiceInk | Voice Buddy | 我们的独特优势 / 改进空间 |
| :--- | :--- | :--- | :--- |
| **底层推理生态** | `whisper.cpp` / `FluidAudio` (Parakeet) + 可选第三方云端 API | **Apple Silicon 原生 MLX (`mlx-swift`)** + **Qwen3 (千问)** 生态 | **我们的优势**：千问在中文、中英混合、口语自纠错语义理解上大幅领先 Whisper；且 MLX 在 Apple M 系列芯片上的能效比更高。 |
| **浮窗交互与动效** | 基础深色悬浮窗，展示简单识别文字 | **三态视觉层级（纯白定稿、青色修改胶囊、流式微光）** + **光标飞入微动效** + **双侧 16 柱对称音浪** | **我们的优势**：视觉层次与动态微交互极为细腻，达到 Apple 原生级空间连续感。 |
| **场景规则体系** | 完备的应用模式（Modes）与规则管理 | 统一的全局整理力度（原文/轻微/适度/完全重写） | **改进空间**：亟需引入应用级场景化配置（见下文路线图）。 |
| **专有词汇与自学习** | 支持自定义词汇与纠错学习 | 尚未支持词典 | **改进空间**：后续应引入自定义专有名词表。 |
| **历史归档与检索** | 具备历史记录搜索看板 | 仅保留当次结果在恢复面板 | **改进空间**：需增加本地持久化历史列表。 |

## 4. 后续演进规划（Actionable Roadmap）

结合 VoiceInk 的成熟经验与 Voice Buddy 现有的架构优势，后续迭代方向规划如下：

### 第一阶段（P1 近期迭代）：应用级场景规则与自定义词库
1. **应用感知场景配置（App-Specific Polish Profiles）**：
   - 在设置中增加“应用偏好”子页面，支持预设或添加应用映射：
     - **编程类应用**（Xcode, VS Code, Cursor, Terminal）→ 倾向代码命名规范、符号保留。
     - **办公沟通类应用**（Mail, Word, 微信, Slack, 飞书）→ 规范书面标点，适度口语润色。
   - 流水线在收到 `targetAppName` 时自动切换对应的 Prompt 引导词。
2. **用户专有词典（Custom Vocabulary List）**：
   - 设置中提供自定义专有名词表（支持按逗号或换行添加词汇）。
   - 将词汇表作为 Initial Prompt 注入 ASR 或作为轻量后处理确定性替换字典。

### 第二阶段（P2 中期迭代）：本地历史记录与检索
1. **历史记录看板（History Tab）**：
   - 在主界面“结果”标签页引入历史记录侧边列表或瀑布流。
   - 每条记录包含：时间、目标应用图标与名称、原始文本与润色文本。
   - 提供快捷搜索框与一键复制按钮。
2. **隐私策略与生命周期管理**：
   - 遵循离线与隐私优先原则，默认不保存音频文件；
   - 历史文本提供自动清理周期设置（如“保留 3 天”、“保留 7 天”、“永久”、“完全不保存”）。

### 第三阶段（P3 远期拓展）：全局 AI 助手模式
1. **双模热键机制**：
   - 快捷键 1：常规听写上屏（当前核心功能）。
   - 快捷键 2：AI 助手指令模式（读取当前选中文本 + 用户口述指令 → 本地 Qwen 执行并给出替换建议）。
